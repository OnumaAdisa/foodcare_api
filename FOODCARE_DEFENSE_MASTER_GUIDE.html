1. บทนำ วัตถุประสงค์ และจุดขายของโครงงาน (Overview & Value Proposition)

1.1 ที่มาและความสำคัญ (Problem Statement)

ปัญหา ขยะอาหาร (Food Waste) ในระดับครัวเรือนจัดเป็นหนึ่งในปัญหาสำคัญระดับโลก โดยเฉลี่ยแล้วอาหารที่ถูกซื้อมาบริโภคมากกว่า 30% ถูกทิ้งไปโดยเปล่าประโยชน์ สาเหตุหลักเกิดจาก:

  • ลืมวันหมดอายุ: ซื้อของสดมาแช่ไว้ในตู้เย็น ลึกจนมองไม่เห็น หรือไม่ได้บันทึกวันหมดอายุ ทำให้ของเน่าเสียก่อนนำมารับประทาน
  • ขาดการวางแผนเมนู: ผู้ใช้ไม่รู้ว่าจะนำวัตถุดิบที่เหลืออยู่ในตู้เย็นไปทำเมนูอะไรดี จึงตัดสินใจซื้ออาหารใหม่แทนการใช้วัตถุดิบเดิม
  • ขาดการสื่อสารในครอบครัว: สมาชิกในบ้านต่างคนต่างซื้อของเข้าบ้านโดยไม่รู้ว่าในตู้เย็นมีของสิ่งนั้นอยู่แล้ว เกิดการซื้อซ้ำซ้อน (Duplicate Purchases)

1.2 โซลูชันของโครงงาน FoodCare

FoodCare ได้รับการออกแบบให้เป็นระบบจัดการตู้เย็นอัจฉริยะแบบ Closed-Loop Inventory ที่เชื่อมโยงการทำงานตั้งแต่การนำเข้าวัตถุดิบ การติดตามความสด การปรุงอาหาร จนถึงการซื้อของใหม่อย่างครบวงจร:

💡 4 เสาหลักของ FoodCare ที่ต้องเน้นย้ำกับกรรมการ:
  1. Smart Tracking & Expiry Countdown: คำนวณเปอร์เซ็นต์ความสดคงเหลือ (% Freshness) และแจ้งเตือนของใกล้หมดอายุล่วงหน้า
  2. AI Vision Object Detection: สแกนภาพถ่ายวัตถุดิบและนำเข้าสู่ระบบอัตโนมัติด้วย Google Gemini และ MobileNet
  3. AI Chef & Automatic Stock Deduction: ให้ Gemini AI คิดค้นสูตรอาหารตามวัตถุดิบที่มีจริง และเมื่อปรุงเสร็จ ระบบจะตัดสต็อกวัตถุดิบในตู้เย็นให้อัตโนมัติ (Cooking Mode)
  4. Shared Household Fridge: สมาชิกในครอบครัวสามารถแชร์ตู้เย็นและรายการซื้อของร่วมกันได้ผ่านรหัส Invite Code

2. สถาปัตยกรรมระบบและเทคโนโลยี (Architecture & Tech Stack)

โครงงาน FoodCare ออกแบบตามสถาปัตยกรรมแบบ Client-Server Architecture (RESTful API) แยกส่วนการทำงานระหว่าง Front-end และ Back-end อย่างชัดเจน (Decoupled Design) ทำให้ดูแลรักษาง่ายและรองรับการขยายตัวในอนาคต:

ส่วนงาน (Layer) เทคโนโลยีที่ใช้ หน้าที่และเหตุผลทางวิศวกรรม
Frontend (Client) React 19, Vite 8, @tanstack/react-router, Tailwind CSS v4, Lucide React • React 19 & Vite: ให้ประสิทธิภาพการประมวลผล Virtual DOM สูง และเวลา Build ที่รวดเร็ว
• TanStack Router: จัดการ Client-side Routing ได้อย่างปลอดภัยและมี Type-safety
• Tailwind CSS v4: ตกแต่ง UI แบบ Utility-first สวยงาม ทันสมัย และ Responsive รองรับทุกหน้าจอ
Client-side AI TensorFlow.js (@tensorflow/tfjs), MobileNet วิเคราะห์และตรวจจับภาพวัตถุดิบบนเว็บเบราว์เซอร์ได้ทันทีโดยไม่ต้องส่งข้อมูลรูปภาพขึ้น Server ช่วยลดแบนด์วิดท์และความหน่วง
Backend (Server) Node.js, Express.js 5, express-session, bcrypt, nodemailer • Express.js 5: จัดการ RESTful API endpoints และ Asynchronous middleware ได้อย่างรวดเร็ว
• express-session: ควบคุมสถานะการเข้าสู่ระบบผ่าน HttpOnly Cookies มีความปลอดภัยสูง ป้องกัน XSS Attacks
• bcrypt: เข้ารหัสผ่านของผู้ใช้ด้วย Salt rounds ป้องกันข้อมูลรั่วไหล
• nodemailer: ส่งรหัส OTP 6 หลักผ่าน SMTP ไปยังอีเมลจริงเพื่อยืนยันตัวตน
Database MySQL / MariaDB, mysql2 (Connection Pool) • ฐานข้อมูลเชิงสัมพันธ์ (Relational Database) มี Foreign Key Constraints และ Cascading Rules ควบคุมความสมบูรณ์ของข้อมูล
• ใช้ mysql2/promise แบบ Connection Pooling (10 Connections) ป้องกันปัญหาเซิร์ฟเวอร์ค้างเมื่อมีคำขอพร้อมกัน
External AI Service Google Generative AI (Gemini 3.5 Flash / Flash Lite) • สร้างสรรค์สูตรอาหารตามวัตถุดิบในตู้เย็น (Prompt Engineering บังคับตอบกลับเป็น Structured JSON)
• วิเคราะห์ภาพวัตถุดิบความละเอียดสูง (Gemini Vision) พร้อมระบบ Fallback รองรับกรณีเน็ตขัดข้อง

ภาพที่ 4.1 แผนภาพ Use Case Diagram แสดง Actors และความสัมพันธ์ Include / Extend
🔍 คำอธิบายความสัมพันธ์ที่กรรมการมักจะถาม:
  • Actor ผู้ใช้ (User): มีปฏิสัมพันธ์กับ UC-01 ถึง UC-08 ครอบคลุมการยืนยันตัวตน, จัดการบ้าน, เพิ่ม-ลบของสด, ดูเมนู, และซื้อของ
  • Actor ระบบ (System Background Process): รับผิดชอบ UC-09 (แจ้งเตือนของใกล้หมดอายุอัตโนมัติ) โดยตรวจสอบวันหมดอายุเทียบกับเวลาปัจจุบัน
  • «extend» (สแกนวัตถุดิบด้วย AI $ ightarrow$ UC-04 เพิ่มวัตถุดิบ): การสแกนภาพเป็นทางเลือกเสริม (Optional) ในการเพิ่มของสด ผู้ใช้จะเลือกกรอกด้วยมือหรือใช้ AI สแกนก็ได้
  • «include» (UC-07 ทำอาหาร $ ightarrow$ UC-05 ตัดสต็อก): เมื่อผู้ใช้ทำอาหารเสร็จสิ้น ระบบ จำเป็นต้อง (Mandatory) คำนวณตัดสต็อกวัตถุดิบในตู้เย็นออกทันที
  • «include» (UC-08 ซื้อของ $ ightarrow$ UC-04 เพิ่มวัตถุดิบ): เมื่อซื้อสินค้าในรายการ Shopping List ครบแล้ว ระบบจะย้ายรายการนั้นเข้าตู้เย็นเป็นของสดโดยอัตโนมัติ

6.1 Middleware ซิงค์เซสชันและฟื้นฟูอัตโนมัติ (server.js บรรทัด 57-123)

ทำไมต้องมีโค้ดนี้? เพื่อแก้ปัญหา Session หลุดเมื่อเซิร์ฟเวอร์รีสตาร์ท หรือการร้องขอข้าม Port ระหว่าง 5173 (Vite) กับ 8080 (Express): 

// server.js บรรทัด 57-123
app.use((req, res, next) => {
    let userId = req.session && req.session.user
        ? Number(req.session.user.user_id || req.session.user.id || 0)
        : 0;

    // ถ้า Session หลุด ให้ฟื้นฟูจาก Header หรือ State ที่แนบมา
    if (!userId) {
        if (req.headers['x-user-id']) userId = Number(req.headers['x-user-id']);
        else if (req.body?.userId) userId = Number(req.body.userId);
        else if (lastActiveUserId) userId = lastActiveUserId; // Local fallback
    }

    if (userId > 0) {
        // ดึงข้อมูลผู้ใช้และกลุ่มบ้านจริงล่าสุดจาก Database เพื่อให้ตู้เย็นซิงค์เสมอ
        const syncSql = `
            SELECT u.user_id, u.username, u.email,
                   COALESCE(u.household_id, hm.household_id) AS household_id,
                   h.name AS household_name, h.invite_code
            FROM users u
            LEFT JOIN household_members hm ON hm.user_id = u.user_id
            LEFT JOIN households h ON h.id = COALESCE(u.household_id, hm.household_id)
            WHERE u.user_id = ? LIMIT 1
        `;
        db.query(syncSql, [userId], (err, rows) => {
            if (!err && rows.length > 0) {
                req.session.user = rows[0];
            }
            next();
        });
        return;
    }
    next();
});

6.3 การคำนวณหักสต็อกวัตถุดิบใน Cooking Mode (cooking.jsx บรรทัด 55-90)

// cooking.jsx บรรทัด 55-90
const calculateDeductPercent = (requiredQtyStr, fridgeQtyStr) => {
    const reqMatch = String(requiredQtyStr || "").match(/[\d.]+/);
    const fridgeMatch = String(fridgeQtyStr || "").match(/[\d.]+/);

    if (reqMatch && fridgeMatch) {
        const reqNum = parseFloat(reqMatch[0]);
        const fridgeNum = parseFloat(fridgeMatch[0]);

        if (fridgeNum > 0) {
            if (reqNum >= fridgeNum) return 100; // ใช้หมดเกลี้ยง หัก 100% (ลบออก)
            return Math.round((reqNum / fridgeNum) * 100); // หักตามสัดส่วนจริง เช่น 50%
        }
    }
    return 100;
};

8. คลังคำถาม-คำตอบรับมือกรรมการ (Comprehensive Defense Q&A)

Q1 ทำไมถึงเลือกทำโปรเจกต์นี้ มีแอปแนวนี้อยู่แล้ว ระบบของเราต่างจากคนอื่นอย่างไร?
แนวทางการตอบ:
"แอปจัดการตู้เย็นทั่วไปส่วนใหญ่มักทำหน้าที่เป็นเพียง 'สมุดจด' (Passive Inventory) ซึ่งผู้ใช้ต้องคอยพิมพ์บันทึกเองและดูเอง แต่ FoodCare แตกต่างด้วย 3 จุดเด่นหลัก ครับ:
1. Active Food Waste Reduction: มีระบบ AI Chef ที่วิเคราะห์จากของที่มีอยู่จริงในตู้เย็น พร้อมโหมดทำอาหาร (Cooking Mode) ที่หักสต็อกของสดให้อัตโนมัติ ทำให้ผู้ใช้มีแรงจูงใจในการใช้วัตถุดิบให้หมดก่อนเน่าเสีย
2. Household Collaboration: ออกแบบมาเพื่อคนในบ้านร่วมกัน ไม่ใช่แค่คนเดียว มีตู้เย็นส่วนกลางและรายการซื้อของที่ทุกคนในบ้านเห็นพร้อมกัน ป้องกันการซื้อซ้ำซ้อน
3. Seamless Automation: นำ Computer Vision เข้ามาช่วยตรวจจับวัตถุดิบผ่านภาพถ่าย ทำให้ลดภาระการพิมพ์ของผู้ใช้ลงอย่างมากครับ"
Q2 ระบบยืนยันตัวตนใช้ Session หรือ JWT? ทำไมถึงเลือกใช้วิธีนี้?
แนวทางการตอบ:
"ระบบของเราเลือกใช้ Server-side Session ร่วมกับ HttpOnly Cookie (ผ่าน express-session) ครับ เหตุผลคือ:
1. ความปลอดภัยสูงกว่า: HttpOnly Cookie ไม่สามารถเข้าถึงได้ผ่าน JavaScript ฝั่ง Client ทำให้ป้องกันการถูกขโมย Token จากช่องโหว่ XSS (Cross-Site Scripting) ได้ 100%
2. Revocation ควบคุมง่าย: เมื่อผู้ใช้กด Logout หรือถูกเปลี่ยนสิทธิ์ในกลุ่มบ้าน เซิร์ฟเวอร์สามารถสั่งทำลาย Session ได้ทันที ไม่เหมือน JWT ที่มักมีปัญหาเรื่อง Token Invalidation จนกว่าจะหมดอายุครับ"
Q3 ถ้าเชื่อมต่อ Google Gemini API ไม่ได้ หรืออินเทอร์เน็ตหลุด ระบบ AI Chef จะเป็นอย่างไร?
แนวทางการตอบ:
"เราออกแบบระบบให้มี Graceful Degradation (ความทนทานต่อข้อผิดพลาด) ครับ ในฟังก์ชัน /api/recipes/suggest เรามีฟังก์ชัน getFallbackRecipes() เตรียมไว้ หากเรียก Gemini API ล้มเหลวหรือเกินโควตา ระบบจะหยิบเมนูอาหารมาตรฐานที่เข้ากับวัตถุดิบหลักขึ้นมาแสดงผลทันที พร้อมข้อความแจ้งเตือนผู้ใช้ ทำให้หน้าเว็บไม่ค้างหรือเกิดหน้าขาว (White Screen of Death) ครับ"
Q4 ระบบป้องกัน SQL Injection อย่างไร และรหัสผ่านเก็บอย่างไร?
แนวทางการตอบ:
"1. SQL Injection: เราใช้ Parameterized Queries (เครื่องหมาย ?) ผ่านไลบรารี mysql2 ในทุกคำสั่ง SQL 100% ซึ่งตัวขับฐานข้อมูลจะทำการ Escape ค่าตัวแปรแยกจากตัวคำสั่ง SQL ทำให้ผู้ไม่หวังดีไม่สามารถแทรกคำสั่ง SQL เข้ามาโจมตีได้
2. Password Security: รหัสผ่านไม่เคยถูกบันทึกเป็น Plaintext แต่จะผ่านการ Hash ด้วยอัลกอริทึม bcrypt ร่วมกับการ Salt แบบสุ่ม ทำให้แม้ข้อมูลฐานข้อมูลจะรั่วไหล ก็ไม่สามารถย้อนกลับเป็นรหัสผ่านเดิมได้ครับ"
Q5 ทำไมถึงมีทั้ง TensorFlow.js (MobileNet) และ Google Gemini Vision?
แนวทางการตอบ:
"เราออกแบบเป็น Hybrid AI Architecture ครับ:
• MobileNet (Client-Side): เน้นความเร็ว สามารถจำแนกวัตถุดิบพื้นฐานได้แบบ Real-time บนเบราว์เซอร์ ทำงานได้แม้เน็ตช้า ไม่เสียค่า API

    สิ่งที่ต้องพูด: "นี่คือฟังก์ชันไฮไลต์ครับ AI จะหยิบรายการวัตถุดิบที่มีจริงในตู้เย็น ส่งไปประมวลผลผ่าน Google Gemini เพื่อคิดค้นเมนูอาหารไทยและสากล พร้อมระบุวัตถุดิบ เครื่องปรุง และขั้นตอนการทำอย่างละเอียดครับ"

  5. สาธิตโหมดทำอาหาร (Cooking Mode) และการตัดสต็อกอัตโนมัติ

    สิ่งที่ต้องทำ: เลือกเมนูอาหารหนึ่งเมนู กดปุ่ม 'เริ่มทำอาหาร (Cooking Mode)' จากนั้นกดปุ่ม 'ทำอาหารเสร็จสิ้น' แล้วพากรรมการกลับมาดูหน้าตู้เย็น
    สิ่งที่ต้องพูด: "เมื่อเราทำอาหารเสร็จ ระบบจะคำนวณหักเปอร์เซ็นต์วัตถุดิบในตู้เย็นให้โดยอัตโนมัติ จะเห็นว่าของสดที่ใช้ไป ปริมาณลดลงจริงตามสัดส่วน และหากใช้หมด 100% รายการนั้นจะถูกล้างออกจากตู้เย็นทันทีเพื่อไม่ให้ค้างสต็อกครับ"

  6. เชื่อมโยงไปยังรายการซื้อของ (Shopping List: Complete Loop)

    สิ่งที่ต้องทำ: เปิดหน้า Shopping (รายการซื้อของ) ติ๊กถูกสินค้า แล้วกดย้ายเข้าตู้เย็น
    สิ่งที่ต้องพูด: "เมื่อของในตู้เย็นหมด ผู้ใช้สามารถจดลง Shopping List ได้ และเมื่อไปซื้อของกลับมา เพียงติ๊กถูกแล้วกดบันทึก สินค้าก็จะถูกโอนย้ายกลับเข้าสู่ตู้เย็นเป็นของสดชิ้นใหม่ทันที ครบวงจรการทำงานแบบ Closed Loop ครับ"

10. ตารางสรุปสิ่งที่ต้องท่องจำก่อนเข้าห้องสอบ (Must-Memorize Summary)

หัวข้อที่ต้องจำคำตอบแบบสั้น กระชับ สำหรับพูดในห้องสอบ
ชื่อโครงงาน FoodCare — ระบบจัดการตู้เย็นอัจฉริยะ ลดขยะอาหาร (Smart Refrigerator & Food Waste Reduction System)
